Этап 1. Основы тестирования

Прочитайте требование и запишите, что должен увидеть пользователь. Тест-кейс связывает начальные условия, действия и ожидаемый результат. Когда фактический результат расходится с требованием, проверьте, повторяется ли расхождение. Воспроизводимое отклонение можно описать в баг-репорте.

Проверка за вечер

Составьте таблицу с четырьмя колонками «Имя», «Длина», «Ожидание», «Факт». Проверьте пустое поле и строки из 2, 3, 12 и 13 букв. Позитивные проверки показывают, что допустимое имя принимается. Негативные показывают, что при недопустимом вводе форма остаётся открытой и сообщает об ошибке.

Этап 2. Базовый Python

Перенесите строки таблицы в программу. Переменная хранит значение, словарь связывает имя с ожидаемым результатом, список объединяет примеры. Цикл for перебирает их по очереди, условие if/else выбирает сообщение, а print() выводит его в терминал.

Проверка за вечер

Сохраните код в файл names.py и запустите python names.py из его папки. Функция valid_name здесь играет роль учебной реализации, которую вы проверяете.

def valid_name(name):
    return name.isalpha() and 3 <= len(name) <= 12

cases = [
    {"name": "Ян", "expected": False},
    {"name": "Ева", "expected": True},
]
for case in cases:
    actual = valid_name(case["name"])
    if actual == case["expected"]:
        print(case["name"], "— проверка прошла")
    else:
        print(case["name"], "— расхождение", actual)

Самопроверка. Оба примера проходят. Добавьте пустую строку, имена из 12 и 13 букв и строку «Ев1». Замените нижнюю границу в функции на 4. Скрипт должен показать расхождение для имени «Ева». Верните границу 3 и запустите ещё раз.

Этап 3. Git и базы данных

Сохраните версию проверки, которую сможет запустить коллега. В папке с names.py команда git init -b main создаст репозиторий. Проверьте список изменений командой git status, подготовьте файл через git add names.py и сохраните снимок командой git commit -m "Проверка границ имени".

Создайте пустой репозиторий в GitHub или GitLab. Привяжите его командой git remote add origin АДРЕС, подставив HTTPS-адрес репозитория. Отправьте ветку через git push -u origin main. После этого git pull загружает изменения из связанной ветки и объединяет их с локальной работой.

Проверка за вечер

При регистрации приложение обычно сохраняет пользователя в базе. Чтобы освоить проверку записи, откройте новую учебную базу SQLite и выполните запросы в её SQL-редакторе. Первый создаёт таблицу, второй добавляет учебного пользователя, третий выбирает только строки с нужным именем.

Этап 4. Автотесты с pytest и Selenium

Переложите вывод результатов на pytest. Перенесите функцию valid_name в отдельный файл validation.py. Рядом создайте test_names.py с кодом ниже. Установите pytest командой python -m pip install pytest, затем выполните python -m pytest -q из этой папки.

import pytest
from validation import valid_name

@pytest.mark.parametrize("name, expected", [
    ("Ян", False), ("Ева", True), ("", False),
    ("А" * 12, True), ("А" * 13, False), ("Ев1", False),
])
def test_name(name, expected):
    assert valid_name(name) == expected

Каждая пара запускается как отдельная проверка. Вы увидите 6 passed. Если изменить нижнюю границу на 4, pytest укажет аргумент «Ева» и покажет рядом фактическое и ожидаемое значения.
